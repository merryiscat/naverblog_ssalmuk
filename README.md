# naverblog_ssalmuk — 네이버 블로그 완전 자동 운영 파이프라인

네이버 블로그를 **사람 개입 없이** 운영해서, 글이 네이버 **AI 브리핑**(검색 상단의 AI 요약)에
인용되게 만들고, 그 인용수로 **네이버 메이트**(월 지원금을 주는 창작자 프로그램)에 선정되는 것을
목표로 하는 프로젝트입니다.

핵심 아이디어 한 줄: **"AI 브리핑은 뜨는데 마땅한 출처가 없는 질문"을 데이터로 찾아,
그 질문에 잘 답하는 구조화된 글을 매일 자동으로 써서 올린다.**

## 어떻게 돌아가나 — 하루 사이클

미니PC(Ubuntu)에서 systemd 서비스로 상주하며, 매일 이 순서로 돕니다:

| 시각 (±지터) | 단계 | 하는 일 |
|------|------|---------|
| 04:00 | 주제 발굴 | 검색광고 API로 연관키워드 확장 → 골든키워드 점수(검색량÷문서수) → LLM이 "쓸 가치" 채점 → 오늘의 주제 1~2개 선정 |
| 08:30 | 글 생성 | 리서치 → GPT 작문(인용 잘 되는 템플릿 강제) → **품질 게이트**(6차원 채점, 사실성 미달이면 발행 포기) |
| 11~21시 랜덤 | 발행 | Playwright로 스마트에디터 자동 발행 → 비로그인 브라우저로 실제 게시 재확인 |
| 21:30 | 측정 | 프로필 인용수 / 검색 순위 / 내 글이 브리핑에 인용됐는지 관찰 |
| 22:30 | 자가 보정 | 그날 데이터를 보고 LLM이 내일 방향 결정 → **텔레그램 일일 리포트** 발송 |
| 화·금 15:00 | 경쟁 관찰 | 브리핑에 인용되는 남의 글 구조 분석 + **인용 공백**(출처가 낡은 질문) 탐지 |

사람은 텔레그램 리포트만 봅니다. 시스템이 못 푸는 상황(캡차, 세션 만료)이 생기면
🚨 소환 알림이 옵니다.

## 왜 이렇게 설계했나

- **모든 시각에 지터, 하루 1~2건만** — 네이버는 "글이 아니라 작성자의 활동 패턴"을 봅니다.
  기계 티가 나는 대량 발행은 제재 대상이라, 사람 같은 리듬이 생존 조건입니다.
- **품질 게이트가 발행보다 우선** — 사실성 점수가 낮으면 그날 발행을 접습니다 (0건 허용).
  네이버 공식 가이드가 "기계적으로 생성된 저품질 대량 콘텐츠"를 걸러낸다고 명시하기 때문입니다.
- **자가 보정은 전권 위임이지만, 규칙 안에서만** — 국면(탐색→가중→수렴)은 LLM이 아니라
  데이터 조건이 전환하고, 같은 결정은 주 1회만 바꿀 수 있습니다(진동 방지). 상세: [docs/loop-design.md](docs/loop-design.md)

### 시스템도 못 넘는 하드 가드레일 4종 (코드 고정)

1. 발행 일 최대 2건
2. 월 운영비 3만원 초과 시 자동 정지 (모든 LLM 호출이 단일 게이트웨이로 비용 적산)
3. 공감·댓글·서로이웃 자동화 금지 (계정 제재 사유)
4. 품질 게이트 미달 글 발행 금지

## 프로젝트 구조

```
src/
  config.py      설정·가드레일 상수·모델 단가표
  db.py          SQLite 스키마 (topics/posts/metrics/rankings/decisions/policy/competitors/costs)
  guardrails.py  발행 상한·예산 상한 검사
  llm.py         OpenAI 단일 게이트웨이 (비용 적산 + 예산 검사)
  naver_api.py   네이버 검색 API + 검색광고 API(HMAC 서명)
  topics.py      C1 주제 발굴 (메이트 공식 10분야 정렬)
  writer.py      C2 글 생성 + 품질 게이트
  publisher.py   C3 발행 (스마트에디터 자동화 + 실게시 검증)
  metrics.py     C4 측정 (인용수 위젯 파싱 + 글별 인용 관찰)
  steering.py    C5 일일 자가 보정 + 텔레그램 리포트
  competitors.py C6 경쟁·공백 관찰
  scheduler.py   전체를 하루 리듬으로 묶는 상주 스케줄러
scripts/         단독 실행·셋업 도구 (setup.py = 최초 셋업 위저드)
docs/            LLM이 유지하는 프로젝트 위키 — 시작은 docs/index.md
deploy/          systemd 서비스 유닛
```

기술적으로 재미있는 부분 둘:
- **스마트에디터에 서식 있는 글 넣기** — 네이버 에디터는 마크다운·HTML 모드가 없습니다.
  에디터의 키 입력 수신 iframe에 **합성 붙여넣기 이벤트로 HTML을 주입**하면
  표·소제목이 네이티브 컴포넌트로 변환됩니다 (`publisher.py`).
- **발행을 믿지 않기** — 발행 버튼이 눌려도 성공으로 치지 않고, 비로그인 브라우저로
  공개 URL을 열어 실제 게시를 확인합니다.

## 시작하기

요구: Python 3.13+, [uv](https://docs.astral.sh/uv/), 네이버 계정(블로그),
OpenAI API 키, 네이버 검색광고 API 키(무료·광고주 가입), 텔레그램 봇.

```bash
uv sync
uv run playwright install chromium
uv run python scripts/setup.py       # 셋업 위저드 — 로그인·키 발급을 단계별 안내
uv run python scripts/verify_keys.py # 전체 키 실호출 검증 (5/5 나오면 준비 끝)
```

개별 단계 실행(테스트용):

```bash
uv run python scripts/run_topics.py       # 주제 발굴
uv run python scripts/run_writer.py       # 글 생성 + 게이트
uv run python scripts/run_publisher.py    # 발행 (⚠️ 실제로 올라감)
uv run python scripts/run_metrics.py      # 측정
uv run python scripts/run_steering.py     # 보정 + 리포트
```

상시 운영은 서버에 systemd로 올립니다 → [docs/deploy.md](docs/deploy.md).
**서버 가동 후에는 개발 PC에서 발행 계열 스크립트를 돌리지 마세요** (이중 발행 방지).
