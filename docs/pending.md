**조건형 안건 운영 원칙 (2026-09-04, ohmyPM 게시판 논의에서 채택)**
- 조건이 걸린 안건은 "조건이 켜졌는데 아무도 모르는" 상태가 가장 위험하다 — 실제로 출처 권위 강화 안건의 조건(첫 ai_cited)이 08-26에 충족됐는데 09-04에야 발견됐다(약 열흘 지연). 조건을 적을 때는 **그 조건을 누가·언제 확인하는지**(감시 주체: 주기 점검, 알림, 훅)도 함께 적는다.
- 누적형 조건("주 3건 이상", "월 3건+", "2회 재지적" 등)은 주기 점검으로 세면 점검 주기만큼 발견이 늦는다 — 이상적으로는 **해당 이벤트를 기록하는 순간에 개수를 세서 임계 도달을 그 자리에서 알리는 것**(기록 훅 카운트, 게시판 Ts_skin_maker 담당과의 논의 결론). 코드 구현은 별도 안건이며, 그 전까지는 주기 점검(pending 재부상 훅) 때 임계 숫자를 실제로 세는 단계로 대신한다.
- 조건이 충족돼 사용자 결정이 나면, **결정 내용과 날짜를 이 대장에 남기고 행을 닫는다** — 그래야 같은 안건이 조건 충족 상태로 반복해서 떠오르지 않는다.
