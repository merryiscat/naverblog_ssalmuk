# naverblog_ssalmuk — 네이버 메이트 지원금 파이프라인

> 킥오프 인터뷰 1부 요약 (2026-08-15, kickoffpack PLAYBOOK 절차).
> 2부(유즈케이스)·3부(스택 확정) 결과가 나오면 이 문서를 갱신한다.

## 목표

네이버 블로그를 운영해 **네이버 메이트**에 선정되어 **매월 30만원 지원금**을 꾸준히 받는다.
처음부터 되지 않는다는 전제 하에, 매 사이클 **관찰 → 생산 → 측정 → 보정** 루프를 돌려 접근한다.

- 성공 기준: 메이트 선정 (매월 갱신되므로 "연속 선정"이 유지 목표)
- 중간 지표: AI 브리핑 피인용 발생 → 피인용 수 증가 → 선정권(상위 ~3,000명) 진입

## 네이버 메이트 프로그램 구조 (2026-08 조사, asserted)

- 선정 기준: **AI 브리핑 피인용 수**. 매월 상위 약 3,000명 선정, 월 30만원.
  분야 우수자 300만/최상위 1,000만(스페셜 — 전문성·활동성·신뢰도·반응 종합).
- 자격 1개월 유지, 매월 갱신, 연속 선정 가능. 2026년 6월 시작(베타).
- 주제는 최근 생산 콘텐츠 기준 자동 분류 (상위 10개 분야 / 하위 25개 주제).
- **어뷰징 필터 (공식 발언)**: "글 단위가 아니라 그 글을 쓴 사람이 네이버에서 얼마나
  정상적인 패턴으로 활동했는지"를 본다. → 대량 자동 발행 패턴은 역효과·계정 저품질 리스크.
- 출처: ZDNet 2026-05-28 (https://zdnet.co.kr/view/?no=20260528132349),
  네이버 보도자료 (https://www.navercorp.com/media/pressReleasesDetail?seq=10034478)

## 1부 확정 사항

| 항목 | 결정 |
|------|------|
| 출발점 | 네이버 계정 있음, 블로그는 방치 상태 (사실상 제로 스타트 — 신뢰도 축적 기간 필요) |
| 발행 방식 | **완전 자동** (Playwright). 단, 어뷰징 필터 대응으로 사람 같은 빈도·품질 게이트 필수 |
| 주제 | 고정하지 않음 — **AI 브리핑 인용 현황 데이터를 관찰한 뒤 경쟁 약한 주제로 진입** |

| 화면 | 없음 — 텔레그램 리포트로 현황 수신 |
| 저장소 | SQLite 로컬 (키워드 관찰, 발행 이력, 인용 측정치) |
| 위치 | 새 프로젝트 (이 저장소). tokbiseo-server의 패턴(LangGraph 파이프라인, Playwright 발행, 세션 관리)만 참고 이식 |

## 스택 가설 (2부에서 보정, 3부에서 확정)

- Python + uv, SQLite, Playwright(네이버 발행·AI 브리핑 관찰), LLM 작문(OpenAI), 텔레그램 봇 알림
- 참고 자산: `kakaotalk_parser/tokbiseo-server` — LangGraph 멀티에이전트 작문 파이프라인,
  `tistory_service.py`의 storage_state 세션 관리·재로그인 3단 방어 패턴

## 리스크 (인터뷰에서 이미 제기됨)

1. **완전 자동 발행 vs 어뷰징 필터** — 네이버가 작성자 활동 패턴을 명시적으로 본다.
   발행 빈도(하루 1~2건), 품질 게이트, 발행 시각 분산이 필수 조건.
2. 네이버 블로그는 공식 글쓰기 API 없음 — Playwright 자동화는 캡차·기기확인·저품질 리스크 상존.
3. 방치 계정 제로 스타트 — 신뢰도·활동 이력 축적에 수개월 소요 가능. 30만원 도달 전 무수익 구간 김.
4. 메이트는 베타 — 선정 기준·지급 방식이 바뀔 수 있음 (현금 지급은 베타 기간 한정 발언 있음).
5. **네이버 오픈API 축소 (2026-08-16 실화면 확인)** — 신규 앱 등록에서 검색·데이터랩 API가
   제거됐고 검색 API 신규 제휴도 중단. 신규 진입자는 공식 데이터 통로가 검색광고 API뿐 —
   주제 발굴·측정의 스크래핑 의존도가 설계 당시보다 높아짐 (기존 키 보유자는 영향 없음).
